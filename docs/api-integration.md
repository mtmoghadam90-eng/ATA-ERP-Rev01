# اتصال سرویس‌های دیگر به سامانه (API)

این سند برای وصل کردن n8n — یا هر برنامه‌ی دیگری — به سامانه است.

نکته‌ی اصلی در یک جمله: **API تازه‌ای ساخته نشده.** همان REST API‌ای که خودِ
برنامه با آن کار می‌کند، با یک توکن هم قابل استفاده است. هر مجوزی که برنامه
رعایت می‌کند — دسترسی ماژول، دیدن رکوردهای دیگران، دیدن بهای تمام‌شده — عیناً
برای توکن هم رعایت می‌شود، چون همان کد است.

## ۱. صدور توکن

«تنظیمات ← دسترسی API». چهار چیز را انتخاب می‌کنید:

| فیلد | معنی |
|---|---|
| نام توکن | فقط برای شناختن بعدی («n8n — گزارش روزانه») |
| کاربر | **مهم‌ترین انتخاب**: توکن دقیقاً دسترسی همین کاربر را دارد |
| سطح دسترسی | «فقط خواندن» یا «خواندن و نوشتن» |
| اعتبار | تعداد روز، یا خالی برای بدون انقضا |

توکن **فقط یک بار** نمایش داده می‌شود. از آن یک SHA-256 ذخیره می‌شود و نه خودش،
پس بازیابی ممکن نیست؛ اگر گم شد، توکن تازه‌ای صادر و قبلی را باطل کنید.

توصیه: برای هر سرویس یک توکن جدا، و یک حساب کاربری اختصاصی با حداقل دسترسی‌های
لازم (مثلاً کاربری که فقط «پروژه‌ها» و «پیش‌فاکتورها» را می‌بیند و «مشاهده بهای
خرید» را ندارد). آن‌وقت باطل کردن یک سرویس بقیه را از کار نمی‌اندازد.

## ۲. فراخوانی

```
GET http://192.168.1.104:3000/api/projects?page=1&pageSize=50
Authorization: Bearer ata_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

اولین چیزی که باید امتحان کنید:

```
GET /api/me
```

پاسخ، کاربری را که توکن به نام او کار می‌کند برمی‌گرداند. اگر این کار کرد، بقیه
هم کار می‌کند.

### در n8n

گره **HTTP Request**:

- Authentication: `Generic Credential Type` → `Header Auth`
- Name: `Authorization`
- Value: `Bearer ata_…`
- URL: `http://192.168.1.104:3000/api/...`

سامانه روی شبکه‌ی داخلی است و به اینترنت باز نیست، پس n8n هم باید روی همان شبکه
باشد.

## ۳. شکل پاسخ‌ها

هر پاسخ موفق `success: true` دارد. فهرست‌ها صفحه‌بندی شده‌اند:

```json
{
  "success": true,
  "rows": [ … ],
  "total": 412,
  "page": 1,
  "pageSize": 50,
  "totalPages": 9
}
```

`pageSize` حداکثر ۲۰۰ است؛ برای گرفتن همه‌ی رکوردها باید صفحه‌ها را پیمایش کنید.

پارامترهای مشترک هر فهرست: `page`، `pageSize`، `search`، `sort`، `order`
(`asc` / `desc`). نام فیلدهای قابل مرتب‌سازی و فیلتر برای هر endpoint جداگانه
مجاز شده است؛ یک نام ناشناخته نادیده گرفته می‌شود.

خطاها `success: false` و یک پیام فارسی در `error` دارند، به‌همراه یک `code` در
موارد شناخته‌شده (`UNAUTHENTICATED`، `FORBIDDEN`، `DUPLICATE`).

## ۴. تاریخ‌ها و مبالغ

- تاریخ‌ها **شمسی** و به شکل `YYYY/MM/DD` هستند (`issueDate`, `dueDate`, …).
  ستون میلادی هم در پایگاه داده هست ولی API با شمسی کار می‌کند.
- مبالغ ریالی‌اند مگر سند واحد پول دیگری داشته باشد (`currency`).
- جمع‌ها، مالیات، تخفیف و بهای تمام‌شده‌ی نهایی **سمت سرور محاسبه می‌شوند**؛
  فرستادن آن‌ها در بدنه‌ی درخواست اثری ندارد.

## ۵. چند نمونه

پروژه‌های برنده:

```
GET /api/projects?status=%D8%A8%D8%B1%D9%86%D8%AF%D9%87%20(%D9%85%D9%88%D9%81%D9%82)&pageSize=100
```

کالاهای رو به اتمام:

```
GET /api/products/low-stock
```

خلاصه‌ی داشبورد (همان ارقامی که صفحه‌ی اول نشان می‌دهد):

```
GET /api/dashboard
```

ثبت یک وظیفه (نیازمند توکن «خواندن و نوشتن»):

```
POST /api/tasks
Content-Type: application/json

{ "title": "پیگیری پیش‌فاکتور", "priority": "زیاد", "dueDate": "1405/06/10" }
```

پرسیدن سوال از دستیار هوشمند:

```
POST /api/assistant/chat
{ "messages": [ { "role": "user", "content": "روی پروژه ATA-05-19 چقدر سود کردیم؟" } ] }
```

## ۶. آنچه با توکن **نمی‌شود** کرد

دو مسیر عمداً بسته‌اند:

- `/api/api-tokens/*` — توکنی که بتواند توکن بسازد یا باطل کند، از هر تصمیمی که
  درباره‌اش گرفته می‌شود عمر بیشتری دارد.
- `/api/assistant/actions/:id/confirm` — دکمه‌ی تایید دستیار دقیقاً یعنی «یک آدم
  این را دید و پذیرفت»، و درخواستی از یک پلتفرم اتوماسیون همان یک چیزی است که
  نمی‌تواند معنی بدهد. اگر n8n می‌خواهد پیش‌فاکتور بسازد، مستقیماً
  `POST /api/proformas` را صدا بزند؛ آن مسیر صادقانه است.

تغییر رمز عبور هم با توکن ممکن نیست: `/api/change-password` رمز فعلی را می‌خواهد.

## ۷. ابطال و پیگیری

- «آخرین استفاده» در فهرست توکن‌ها نشان می‌دهد سرویس هنوز کار می‌کند یا نه (با
  دقت پنج دقیقه به‌روز می‌شود، تا هر خواندن تبدیل به یک نوشتن نشود).
- **ابطال**، توکن را از کار می‌اندازد و ردیفش را نگه می‌دارد؛ **حذف**، ردیف را
  هم می‌برد. برای چیزی که سابقه‌اش مهم است، ابطال بهتر است.
- صدور، ابطال و حذف هر سه در «گزارش عملکرد» ثبت می‌شوند.
- غیرفعال کردن یک حساب کاربری، همه‌ی توکن‌های آن حساب را هم بی‌اثر می‌کند.
